# AWF Syntax & Consistency Audit — Synthesis of 51 Verified Findings

**Audit question:** is the syntax unnecessarily complex/hacky/inconsistent, and are functionalities unnecessarily inconsistent across backends (native vs docker) and agents/LLMs? **Answer:** the format core and its locked invariants survive the audit intact — no finding requires breaking one. The pain concentrates in five root causes, none of which is "the format is wrong": (1) an adapter-config validation walk that was **designed, documented in three code comments and three adapter specs, and never built**; (2) a **loader that silently drops what it doesn't understand** and swallows the decode errors it does produce; (3) **no written cross-backend execution contract** (cwd, output paths, env, image lifecycle, snapshot scope — each backend improvised); (4) **adapter parity as folklore** — no naming convention, no enforced universal obligations, no author-visible schema/capability reference; (5) an **on-ramp that demands the maximum concept load** while all three first-touch examples (man-page flagship, README, gemini example) are broken or unrunnable as shown.

**Severity distribution (re-rated from evidence, not copied):** 7 critical, 15 high, 19 medium, 9 low, 1 minor.
**All 7 criticals are closed by three small code changes plus two ~30-line adapter patches** (U1, U2, U3, F31, F36 below).

Findings are numbered F1–F51 in the order supplied. `[FR]` = fix requires an explicit format revision (man-page contract change). `[BD]` = behavior is by design; where rated high anyway, the design decision itself is the documented pain.

## C1 — The designed run-start adapter walk was never built

The engine calls `ValidateConfig` only at dispatch (`engine/local_dispatcher_agent.go:182`), mid-run, after earlier steps spent tokens — while `agent/adapter.go:19,68`, `local_dispatcher_agent.go:179-181`, and the codex/droid/goose adapter specs all promise a run-start CLI walk. `awf validate` staying adapter-blind IS by design (purity, `man/awf.1.md:78`); the mid-run failure timing is a build gap, not a decision.

- **F2 adapter-blind validate — CRITICAL** (confirmed). Typo'd keys (`promt:`), missing `prompt`, bad enums, missing API-key envs all pass validate and die mid-run as `permanent_failure`. **Fix = U1** (below). Do NOT extend `awf validate` — env-dependent checks would break its documented hermetic contract; the project already chose run-start in the awf-llm spec.
- **F32 Claude OAuth users pass preflight, die at first dispatch — HIGH** (confirmed; the bare-mode gate itself is locked Phase-5 decision 9/15 and empirically forced — upstream `claude --bare` ignores the OAuth token; the *timing* is not by design). **Fix:** U1 converts it to a pre-container run-start rejection; plus one conditional in `ErrBareRequiresAPIKey.Error()` (mirror in claudesession): when `CLAUDE_CODE_OAUTH_TOKEN` is set, say "set `bare: false` on the step or provide ANTHROPIC_API_KEY/ANTHROPIC_AUTH_TOKEN"; delete the false doc-comment at `agent/claude/adapter.go:124`.
- **F11 role `system_prompt` folded into with: but codex/codexlive reject it — HIGH** [BD: v1 deferral, but `man/awf-workflow.5.md:395-400` oversells with no caveat]. **Fix:** U1 as the backstop (validates the role-merged config at STEP level — registration-level validation false-positives on missing `prompt`); dissolve for codex by accepting `system_prompt` as a delimited prompt preamble (~15 lines; the `<previous verdict>` block at `codex/launch.go:251` is the in-repo prior art), after re-probing the current codex CLI for a native flag; codexlive: prepend only on the thread-creating turn or defer + one man sentence naming the adapters that reject the key.
- **F40 reserved keys inside with: only warn — MEDIUM** [BD: documented warning; recorded rationale argued warning-vs-hoist, never warning-vs-error; the customer hit it live — prestige.yaml nests input_files/output_files in a droid step's with:]. **Fix [FR, one sentence]:** promote AWF1061 to error (severity is not part of the code's API); extend the pass to `react.with`; verified zero collision between the 11 reserved names and any adapter's allowedKeys, pinned by an enforced-invariant test.

### U1 — Run-start with:-config guard (`cli/with_guard.go`)
**Closes/dissolves:** F2 outright; converts F11, F32, F36 (timing half), F40 (with:-key half), F12 (codexlive arm, once enum lands), F19 (element checks, once ported), droid `FACTORY_API_KEY` (makes `man/awf.1.md:552` true) into pre-spend run-start errors; is the systemic guard for the F1 class.
**Sketch:** fourth member of the existing guard family (threaded/persistent/credential, all `(ld, resolver)` walking the same node shapes). For each agent step: `resolver.Lookup(uses)` → `adapter.ValidateConfig(step.With)` on the raw (role-merged, since roles register first) config. Template-safety rule: suppress value errors only when the key's value is a string containing `{{` AND the error is not unknown-key — add one bool `KeyUnknown` to `agent.ErrInvalidConfig` set at the 7 unknown-key sites. Call in `run.go` after role registration, before `backend.Create` and before the log opens (rejected run leaves no state); mirror in `resume.go`. Exit `ExitUsage`. Fix the three stale comments to point at the real guard. Conformance test on the fake backend.
**Must not break:** with:-opacity (the guard never reads keys — it delegates to the named adapter); validate purity (guard lives at run start); interpreter-sole-writer (rejection precedes log open); mechanical outcomes (usage error, not an outcome). Residual: value errors on templated keys still surface at dispatch — unavoidable without resolving templates.

## C2 — Permissive, mute loader

- **F47 unknown step/top-level keys silently ignored — CRITICAL** (confirmed; not by design — `ir/node_unmarshal.go:25` explicitly defers strictness to a validator pass that was never written). GHA muscle memory (`env:`, `name:`, `working-directory:`) and typos of AWF's own keys (`ouput_files:` silently loses artifacts) validate clean and do nothing; worse, unknown keys are **digest-invisible**, so resume pinning can't catch them either. **Fix = U2a.**
- **F43 YAML decode errors swallowed — HIGH** (confirmed; contradicts `frontend/yaml`'s own package doc). Any `run:` one-liner containing `": "` — the dominant `$AWF_OUTPUT` idiom — yields only `AWF_IMPORT_DECODE: decode workflow YAML`, dropping goccy's caret-annotated `[9:10] mapping value is not allowed…`. **Fix = U2b.**
- **F48 bare-int timeout parsed as nanoseconds — HIGH** (confirmed; `timeout: 300` = 300ns, validates clean, every run times out instantly as retryable_failure; the int-parse arm's only consumer is a round-trip test — the "wire form" it exists for has no ingest path). **Fix = U2c.**

### U2 — Strict, talkative loader
**Closes:** F47, F43, F48 outright; delivers the guard that makes F17's rename safe and the error surfacing F51 needs; hardens F38's x-* reservation.
**Sketch:** (a) error-severity **AWF1062 unknown-key pass** (`ir/validate_unknown_keys.go`): allowed-key sets derived by reflecting `json` tags (already test-enforced — no hand table to drift); walker mirrors `unmarshalNode` dispatch; **skip** the opaque `with:` subtree, JSON-Schema values, workflow `outputs:` values; tolerate top-level `x-*` (compose precedent); nearest-key did-you-mean; guard test asserting the whole examples+customer corpus yields zero AWF1062. Plumbing: `frontend/yaml.Decode` additionally returns the stage-1 raw tree, stored as `LoadedModule.RawDoc`. (b) `LoadError.Detail()` composing `Message: Err` (Go `%w` convention), used by `Error()` and both `cli/validate` outputs; relabel AWF_IMPORT_DECODE/READ catalog text ("workflow failed to decode" — fires on root files too). (c) delete the int arm of `ir.Duration.UnmarshalJSON`; error embeds the value ("bare integer 300 not accepted; use `\"300s\"`"); add a Durations grammar paragraph to awf-workflow(5). MarshalJSON stays int-ns → every digest byte-identical.
**Must not break:** with:-opacity (subtree skipped; AWF1061 remains its mirror); digest/pinning (marshal side untouched everywhere); codes append-only; validate remains pure/static.

## C4 — No cross-backend execution contract

- **F25 bwrap tmpfs swallows `$AWF_OUTPUT` — CRITICAL** (confirmed by code read; not by design — darwin fixed the identical bug in 2900f9b, the Linux bwrap arm never got the bind and has zero AWF_OUTPUT integ coverage). On the **preferred** Linux sandbox, every `run:` step with `output_schema` and every `reduce: run:` fails with a misleading "did not write $AWF_OUTPUT" — typed outputs, the format's core pillar, broken by tool availability within one backend. **Fix:** subsumed by U3; interim one-liner `--bind /tmp/awf /tmp/awf` after the `--tmpfs /tmp` at `sandbox_linux.go:106` (host MkdirAll already exists), plus AWF_OUTPUT round-trip integ tests for BOTH Linux arms; repro on cve-runner first per repo policy.
- **F26 shared host-global `/tmp/awf` + shared native workdirs — CRITICAL** [BD: a recorded *deferral with a named follow-up* (slice-4.7 decision 11), not locked, not user-facing]. Concurrent native runs silently commit each other's typed-output bytes (valid-but-foreign JSON passes schema validation — textbook silent data divergence), and native workdirs are keyed by container NAME only, so one run's Destroy `os.RemoveAll`s another's live workspace. **Fix = U3.**
- **F8 no working-directory contract — HIGH** (confirmed; explicitly deferred, not decided). docker exec runs at image WORKDIR, native at the per-run workdir; output_files have no absoluteness check and the man page's own contract example uses `./out/summary.json`; on docker, relative capture is inconsistent within ONE step (moby resolves archive paths against `/`). **Fix:** ~10 lines in `docker/capture.go` — join relative capture paths to the container's `Config.WorkingDir` (one cached ContainerInspect), making write base == capture base on both backends; one man paragraph defining `run:` cwd per backend. Do NOT require absolute output_files (on native, absolute = literal host paths by decision 10).
- **F27 docker never pulls static images — HIGH** (confirmed; an unfulfilled slice-4.5 IOU — runtime map images and compose both self-pull; static image-mode, the man page's own first example, alone fails ExitInfra on a cold cache with an undocumented pre-pull requirement). **Fix:** on ContainerCreate NotFound, call the existing `pullByDigest` and retry once; wrap pull failure in `ImageUnavailableError`; delete the stale precondition comment; doc sentence + fix stale `runtime-design.md:351`. Digest-pinned pull IS "infra rebuilt from the recipe."
- **F5 explicit native silently drops `cmd:`/`keepalive:`/`resources:` — HIGH** (confirmed; image-ignore-with-warning is documented, the other three keys are an unexamined corner — the docs' own "no host equivalent" rationale applies verbatim to a `cmd:` service). **Fix:** fail-closed on `cmd:` and `keepalive: false` in `firstNativeIncompatibleFeature` (reusing the compose-rejection error shape; fires only under explicit `--backend native` since auto routes any static image to docker); enumerate ignored keys (image, resources) in the run-start warning; three doc caveats. ~40 lines.
- **F15 no env channel for run: steps on docker — MEDIUM [FR, BD:** documented carve-out with no recorded rationale; native leaks the entire host env while docker offers nothing — hermeticity cannot be the reason]. **Fix:** workflow `env:` names reach `run:` steps too; the delivery channel is already built and idle (`ResolvedInputs.Env`, proven by AWF_STAGING_ROOT); `--agent-env` stays agent-only. GHA-shaped; deletes the man-page carve-out and its warning.
- **F28 `/work/.awf` literal MUST with no lint — MEDIUM** (partial; the incident's `mkdir /work` failure was the pre-WS-5 ENGINE bug, already fixed in 80390b7 — the surviving footgun is the customer's author-side hardcoded literal, which still validates clean and still breaks on native). **Fix:** warning **AWF3015** on literal `/work/.awf` in `run:`/`reduce.run` (AWF3013 pattern, ~20 lines); optional follow-up: inject the WorkdirResolver-absolute path as native's `$AWF_STAGING_ROOT` value.
- **F29 snapshot scope shrinks on native — LOW** [BD per runtime-design; silent-loss window is narrow since the sandbox write-confines to the snapshotted workdir; the man page's real bug is describing the CoW diff as universal and miscalling native's archive a "diff"]. **Fix:** three doc edits + extend the two existing stderr warnings.
- **F30 sandbox mode tri-modal, never journaled — LOW.** **Fix:** record the resolved label (bwrap|landlock|sandbox-exec|none) as one string in `run.started` and print it at start for all modes.

### U3 — `Caps.OutputRoot` + per-run native workdir root
**Closes:** F25 and F26 with one mechanism, plus deletes the root-owned-`/tmp/awf` perms footgun, the accepted tempfile leak, and the macOS/bwrap sandbox allowance blocks; same pattern later retires the adapters' racing fixed paths (`/tmp/awf-codex-schema.json`, `/tmp/awf-droid-settings.json`, `/tmp/awf-goose`).
**Sketch:** (1) `cli/run.go`/`resume.go`: workdirRoot becomes `<state>/work/<runID>` (mirrors docker's existing runID namespacing; runID is read from the log on resume). (2) `Caps.OutputRoot` beside `Caps.StagingRoot`: docker/fake return `/tmp/awf` (unchanged — container /tmp is private); native returns `.awf/output` workdir-relative. `awfOutputTempPath` takes the root as a parameter. Native Exec cwd and CaptureFiles already handle workdir-relative paths; the workdir is exactly what every sandbox binds RW, so F25 dissolves structurally.
**Must not break:** determinism-via-injection (path stays a pure function of runID+nodePath; runID is the one sanctioned nondeterministic id, persisted in `run.started`); commit = blob-before-journal (tempfile is pre-commit scratch, content-addressed at commit exactly as now); no new seams (rides the existing Backend-caps seam). Net-negative surface.

## C5 — Adapter parity is folklore

Two conventions coexist with no rule: mirror-the-harness (claude `allowed_tools`, droid `enabled_tools`) vs shared-vocabulary (droid's BYOK keys deliberately match awfllm "for cross-adapter consistency"). Universal obligations (gate feedback) have no enforcement, so one adapter simply forgot.

- **F31 codexlive silently drops `Feedback` and `input_files` — CRITICAL** (confirmed; NOT by design — the man page's "Automatic feedback… the author does not wire this up" is unconditional). Worst possible instance: in a warm persistent session the model re-sees its own rejected work but never the judge's critique — repairs degrade into blind identical retries burning `max_attempts`, silently voiding the engine-enforced feedback invariant that is AWF's headline differentiator. **Fix:** hoist the 7 byte-identical marshal-and-prepend blocks into `agent.PrependFeedback` (precedent: `agent.Elide`) and call it in codexlive **before** `promptDigest` (preserves live-replay identity); for input_files, add `Caps.InlineInputFiles` (true only for awfllm) + a fifth dispatcher guard in the existing Threaded/ContextEvidence/PersistentSession family → `permanent_failure` with a named reason. Do NOT implement session-cwd file writes now (third key semantic + unconfined host writes). Conformance test, fake backend.
- **F36 gemini example fails even with the key exported — CRITICAL** (confirmed; plain omission — ANTHROPIC_API_KEY joined `DefaultEnvAllowlist` when its provider landed, GEMINI_API_KEY did not; man page documents "default api_key_env: GEMINI_API_KEY" with no forwarding caveat; preflight checks OPENAI/ANTHROPIC so an OPENAI-key holder gets zero warning). **Fix:** add `defaultGeminiAPIKeyEnv` to `DefaultEnvAllowlist`; make `RequiredEnv()` return `DefaultEnvAllowlist` (without this, fix 1 creates a NEW false preflight warning for gemini-only users); append the remedy to the presence-check error ("forward via workflow `env:` or `awf run --agent-env`" — fixes the whole custom-api_key_env class); man `--agent-env` CSV + ENVIRONMENT entry; tests.
- **F12 effort: two key names, three enums, codexlive unvalidated — HIGH** (confirmed; enum CONTENTS are vendor-verified and defensible [BD]; the key-name split and the codexlive validation hole are gratuitous drift — the repo's own droid BYOK note practices the opposite convention). **Fix:** (1) ship-first one-liner: codexlive validates `reasoning_effort` against codex's six-value enum (closes the fails-mid-run arm). (2) `effort` becomes the canonical documented key on codex/codexlive/droid mapped to each native flag; `reasoning_effort` kept as deprecated alias (the customer sets it ~10×; both present = error). (3) Do NOT unify enums; document `low|medium|high|xhigh` as the portable intersection.
- **F37 output_schema fidelity is a hidden tier — MEDIUM** [BD: two-layer design is conformance-pinned (Bucket 15); the author-invisibility is not — runtime-design explicitly lists "docs" as an intended Caps consumer]. **Fix:** hoist `SchemaDirective` (goose's variant, with worked example) + the three byte-identical `extractJSONObject` copies into `agent/`; publish a THREE-tier table (native flag / API-constrained / directive+parse — awfllm's default is API-constrained, not directive) in the man capability table (U6); doc-sync test rendered from `Capabilities()`.
- **F19 tool permissioning: five shapes + claude's silent element drop — MEDIUM** (codex/codexlive genuinely differ by documented design; the claude/claudesession silent filter of non-string elements is nobody's design — droid already validates element-wise). **Fix:** port droid's element loop into claude+claudesession and delete the launch-time silent filter; rename droid `enabled_tools`/`disabled_tools` → `allowed_tools`/`disallowed_tools` via droid's existing `rejectedKeys` signpost (rename, not alias — aliases turn 5 shapes into 7); codify the naming rule in runtime-design (shared names for cross-harness concepts, harness-native names for unique knobs); 5-row man table (2 of the 5 shapes are currently discoverable only from source).
- **F35 droid steps report no cost/model — MEDIUM** [BD: v1 deferral whose premises are now stale — the model IS on the wire (init event, exact rates.json key) and unpriceable BYOK ids already degrade gracefully to absent]. **Fix:** derive via the pricing table from the init-event model (one live verification run first, per the spec's own condition); add an `UnpricedSteps` marker to roll-ups (`$1.84+ (2 of 5 steps unpriced)`) — fixes the *silent* half for every adapter, forever.
- **F34 goose provider is env-only while model is a with: key — MEDIUM** [BD: v1 deferral predating the BYOK alignment; the spec pre-authorizes the knob]. **Fix:** optional `with: provider` mapped to goose's native `--provider` flag (flag>env precedence dissolves the conflict-policy question); the auth gate reads it for earlier failure; provider enters the definition digest.
- **F33 one PersistentSession capability, two opposite surfaces — MEDIUM** [BD: spec-recorded; softened — the features genuinely differ (engine-owned continuity vs operator-owned supervision); the real residue is a required-key outlier absent from the format reference]. **Fix:** default `session` to hash(RunID, NodePath) (claudesession's scheme; isolation-by-default, sharing stays explicit-by-naming — the containers: idiom); default `cwd` to the workflow-file directory (loader precedent), NOT the staging dir; document codex-live beside claude-code-session in awf-workflow(5).
- **F13 awfllm provider-scoped cache keys: half error, half silent no-op — MEDIUM** [BD documented, but the "no cross-key policing" rationale is superseded three times within the same file]. **Fix [FR, one sentence]:** uniform rule — provider-scoped key `true` on the wrong provider = `ErrInvalidConfig`; zero value valid anywhere; one loop over the three cache bools (also closes the undocumented boolOr silent coercion of `cache_system: "true"` → false); document `cache_context` (currently zero man presence).
- **F23 droid `custom:` prefix mode-dependent — LOW.** **Fix:** idempotent prefix strip/add in launch.go + one man sentence.
