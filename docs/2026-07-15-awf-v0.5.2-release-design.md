# AWF v0.5.2 Release Design

**Date:** 2026-07-15
**Status:** Approved

## Goal

Publish AWF v0.5.2 as a patch release containing the tested Claude Code gated
readiness fixture and its public onboarding documentation. Merge the prepared
branch into `main`, push `main`, create a signed immutable `v0.5.2` tag, and
verify that the tag-triggered GitHub Actions workflow publishes all expected
release assets.

## Version Decision

Use v0.5.2, not v0.6.0. The branch adds documentation and an executable example
but changes no Go runtime, workflow format, schema, adapter, packaging, or
machine contract. A patch bump is therefore the narrowest SemVer-compatible
choice.

## Release Contents

The release includes the already-reviewed branch changes:

- `examples/claude-code-gated/workflow.yaml`, which invokes the Claude Code CLI
  from one AWF agent step, validates its typed output, and passes it through a
  deterministic gate without AWF-level reruns;
- `examples/claude-code-gated/README.md`, which documents subscription-token
  handoff, the explicit native backend, the absolute-state-directory workaround,
  output inspection, cleanup, and troubleshooting;
- root README links to the example and advertises the current release version;
- the corrected readiness design and implementation-plan record.

Release preparation adds:

- a `CHANGELOG.md` section for `0.5.2`, dated 2026-07-15;
- a root README install-version bump from `0.5.1` to `0.5.2`;
- this release design and the corresponding implementation plan.

The example remains pinned to v0.5.1 because that exact public archive and
workflow digest were live-tested. v0.5.2 contains no runtime change, so the
example must not claim that v0.5.2 fixes the discovered macOS native-sandbox
relative-state-path bug. The documented absolute `--state-dir` command remains
the supported path.

## Release Notes

The `0.5.2` changelog entry will describe one documentation/example addition:
a clean-room Claude Code subscription readiness workflow with typed output, an
independent deterministic gate, one Claude Code CLI invocation at the AWF
orchestration level, no AWF-level reruns, and the macOS-safe native invocation.
It will state plainly that AWF does not measure the number of provider requests
inside the CLI and that there are no runtime or workflow-format changes.

## Execution Sequence

1. Prepare and commit the changelog, root install-version bump, and release
   planning documents on `codex/awf-claude-readiness`.
2. Verify the feature branch with `make lint test build`, the release-workflow
   contract tests, a clean diff, and the previously completed live fixture run.
3. Fetch `origin`, confirm `main` has not diverged unexpectedly, then merge the
   named feature branch into local `main` without rewriting history.
4. Run `make lint test build` on the merged `main` tree.
5. Push `main` to `origin`.
6. Create annotated signed tag `v0.5.2` at the verified `main` commit and push
   that tag to `origin`.
7. Monitor the tag-triggered `Release` workflow until it completes.
8. Verify the GitHub Release exists and contains exactly four platform archives
   plus `awf_0.5.2_checksums.txt`; confirm the checksum file lists all four
   archives and the release is not a draft or prerelease.

## Failure Handling

- If the release-preparation or merged-tree gate fails, do not push `main` or
  create a tag; fix on the feature branch and repeat verification.
- If `origin/main` contains unexpected commits, stop before merging and inspect
  the divergence rather than overwriting it.
- If signed-tag creation fails because signing is unavailable, stop before
  pushing a tag; do not substitute an unsigned tag because the maintainer
  contract explicitly requires signing.
- Once `v0.5.2` is pushed, never move or delete it. A bad published release is
  superseded by the next patch version.
- If GitHub Actions fails after the immutable tag is pushed, preserve the tag
  and logs, diagnose the workflow, and release the fix under a later patch tag.

## Verification

Completion requires all of the following evidence:

1. Feature-branch and merged-main `make lint test build` both exit zero.
2. `git status --porcelain` is empty before tagging.
3. Tag `v0.5.2` is annotated, signed, and points at the pushed `main` commit.
4. The GitHub Release workflow succeeds for `v0.5.2`.
5. The published release contains the four expected archives and one checksum
   file, with no missing or extra release archive.
6. The GitHub Release reports `v0.5.2`, is neither draft nor prerelease, and its
   notes come from the `CHANGELOG.md` `0.5.2` section.

## Non-Goals

- No runtime fix for the macOS relative native-state-directory bug.
- No workflow-format, schema, adapter, dependency, or packaging change.
- No Docker image, package-manager distribution, SBOM, or new release tooling.
- No moving or deleting existing or newly published version tags.
